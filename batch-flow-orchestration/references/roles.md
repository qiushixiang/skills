# 角色要点

工单卡提供目标、环境、本单、约束、交付和交接材料；按“## 规范”节读取所列文件的对应章节。不读写 `.batch-flow` 下的状态文件。工单是执行要求的依据，卡片只是统一导出；所有角色、新会话和恢复收到本单当前有效要求及负责人选定的必要材料；历史来源和全量观察保留在记录中，不自动继承为指令。

## 执行者（implement、repair）

cycles-v1 每轮一次实施交付、至多一次原作者返修；复审失败进入下一轮或换人，不能因新工单获得额外返修。主/备用/负责人轮次可配，见[执行轮次](execution-cycles.md)。

- 证据只由 `record`/`snapshot` 生成（命令行见卡片“环境”节）；手写说明不能冒充运行证据；引用异常如实交审阅者判断。

- 在本单范围内实现并验证；提交、推送、发布仅按本单明确授权；证据写入 `<任务>/.batch-flow/records/`，交付中引用绝对路径。
- 在当前调用内持续完成范围内可执行工作，进度通过中间消息汇报，不因完成阶段性草稿而提前结束。按卡中“## 交付”回复：delivery-v2 只填“交付状态：已交付 | 未交付”，不填下一步。已交付直接交独立审阅；未交付说明剩余工作、已尝试办法、为何结束当前调用及需要的处置，由负责人判断同轮继续、结束本轮再派或阻塞。未交付裁决不作质量审阅。历史 intent-v1 卡仍用“下一步：继续 | 交付 | 移交”，旧结果协议依原卡，不混用。
- 环境故障报告实际调用和前检事实，不以自己的 shell 沙箱状态推断受控入口是否可用。
- 返修只处理卡中列出的阻断项，逐项写“阻断关闭”；已审阅通过的部分不得改动。
- 发现本单范围外的问题写进“候选新项”，不顺手修。

## 审阅者（review，含第三方）

- 复跑与证据同样用 `record`/`snapshot` 生成，手写文件不算证据。

- 独立复跑关键验证，不沿用作者结论；只读，不改被审对象。
- FIX_REQUIRED 时每个阻断项一行：编号、返修目标（必须是本审阅组的交付目标）、是否方案级、一句可核验的关闭条件。非阻断建议另写，不影响结论。
- 复审只核对列出的阻断项与回归。

## 自主恢复的执行边界

实施者以卡片的“当前生效的受保护路径权限”和登记来源为准，历史诊断只作背景。额度提案和权限登记交协调工单处理，不代替实际实施。decide/triage 不占实施轮次；新权限、额度和原单重试应形成完整结构化处置，一次批准后由脚本落实。

## 技术负责人（decide、triage）

- decide：读触发与证据，写诊断和 decision.json。包络内技术处置直接执行；只有[六类新增用户决定](user-decisions.md)才提问，权限/额度等变更以结构化动作整包请求批准。技术暂时无解用 blocked 保留原因和最小缺项，次数用尽只作运维暂停和报告。
- delivery-v2 未交付结算裁决只处置执行去向和轮次归属，不判质量通过、不接管审阅。原作者仍可继续时用 continue_run 绑定本单最新未交付运行并给出下一步，同轮续用不另扣轮次；需结束本轮再派时用 retry，驱动器按既有权益选人。不得把未交付改为完成，或另开同义工单增加机会。
- 裁决新开的工作默认是原工单恢复前必须完成的处置；脚本维护等待关系，不能让处置依赖原工单形成环。新单共享既有额度。
- triage：为每个候选项给出去向（并入某交付目标、延期、驳回）并写明理由。
- 不实现、不审阅自己作出裁决的工作；兜底实施时作为执行者按 implement 卡工作。

## 审阅与事实记录

- 独立审阅不修改被审对象。验证副作用、文件变化和提交事实会留存，不能由脚本直接推导产品失败；必要时交负责人诊断。
- 快照 SHA、旧新版本、历史证据异常和采集缺项必须核对并说明影响。证据能否复用、是否需补测、修复是否成立，由审阅者判断；脚本不要求本轮退出 0 或逐一复述快照路径。
- 非阻断建议写在“非阻断建议：”下逐行“- ”，由脚本并入批次分诊。

## 当前工单与必读

先读本单明确列出的必读范围，结合正文中的目标、验收、有效约束和专项工作执行。必需背景由负责人预先编制；遇到缺失或冲突，向负责人指出具体缺项，不自行重放历史暂停、授权或裁决。运行记录是事实来源，不自行改变当前要求。继续遵守范围、真实验证、独立审阅、最小改动、如实报告失败及提交授权边界。


## 提示词章节与审阅范围

实施卡先说明目标、逐项验收及范围/禁止事项，再给本次工作、输入材料、环境留证和交付格式。验收编号仅用于引用，不增加新的要求。专项实施与返修卡中的目标实施约定是边界依据，本次指令只定义本轮要做的差异。

审阅卡先列被审目标和逐项验收，再列阻断边界。实施约定供核对交付是否符合原方案，不是审阅者的实施待办；材料、历史失败和通用规范不能自行扩大验收或要求后续批次提前完成。阻断须对应本组验收未满足/必要证据不足，或本组改动造成的实际回归、可复现缺陷，且绑定本组返修目标、证据与最小关闭条件。范围外发现写非阻断建议，交负责人决定。

完整历史观察保存在结构化派发记录的 versions_and_evidence；正文只给版本及证据来源索引、登记哈希与异常提示。历史输入/观察不是当前命令，不用全量 JSON 淹没任务，也不删除原始审计信息。工程影响与必要复跑仍由角色判断；字段/哈希检查不自动决定产品失败。
