# 角色要点

工单卡提供目标、环境、本单、约束、交付和交接材料；按“## 规范”节读取所列文件的对应章节。不读写 `.batch-flow` 下的状态文件。新会话用当前指令、已批准约束、交付与版本证据交接，不复制完整作者对话。

## 执行者（implement、repair）

- 证据只由 `record`/`snapshot` 生成（命令行见卡片“环境”节）；手写文件不是证据，交付引用它会被退回。

- 在本单范围内实现并验证；证据写入 `<任务>/.batch-flow/records/`，交付中引用绝对路径。
- 按卡中“## 交付”的固定行回复。停止原因如实填写：范围内还有可试路径就是“未完成”，脚本会让你在同一会话继续，不另扣额度。
- 待裁决：只有继续需要改动本卡无权改动的内容（验收、冻结资产、范围、他批接口、预算权限、系统资源门限）时才写。
- 外部阻塞：只有直接调用受控入口出现环境失败时才成立；你自己 shell 的沙箱状态不是证据。
- 返修只处理卡中列出的阻断项，逐项写“阻断关闭”；已审阅通过的部分不得改动。
- 发现本单范围外的问题写进“候选新项”，不顺手修。

## 审阅者（review，含第三方）

- 复跑与证据同样用 `record`/`snapshot` 生成，手写文件不算证据。

- 独立复跑关键验证，不沿用作者结论；只读，不改被审对象。
- FIX_REQUIRED 时每个阻断项一行：编号、返修目标（必须是本审阅组的交付目标）、是否方案级、一句可核验的关闭条件。非阻断建议另写，不影响结论。
- 复审只核对列出的阻断项与回归。

## 自主恢复的执行边界

实施者以卡片的“当前生效的受保护路径权限”和登记来源为准，历史诊断只作背景。额度提案和权限登记交协调工单处理，不代替实际实施。decide/triage 不占实施轮次；新权限、额度和原单重试应形成完整结构化处置，一次批准后由脚本落实。

## 技术负责人（decide、triage）

- decide：读触发与证据，写诊断和 decision.json。包络内技术处置直接执行；只有[六类新增用户决定](user-decisions.md)才提问，权限/额度等变更以结构化动作整包请求批准。技术暂时无解用 blocked 保留原因和最小缺项，次数用尽只作运维暂停和报告。
- 裁决新开的工作默认是原工单恢复前必须完成的处置；脚本维护等待关系，不能让处置依赖原工单形成环。新单共享既有额度。
- triage：为每个候选项给出去向（并入某交付目标、延期、驳回）并写明理由。
- 不实现、不审阅自己作出裁决的工作；兜底实施时作为执行者按 implement 卡工作。

## 审阅者的写入范围（design §24）

- 审阅者只可写 records（`record`/`snapshot` 产物）与交付文本；源码仓库内的变化会被登记为 FAILED 并转技术负责人（`review_modified`），包含验证自动产生的变化。验证方案与副作用边界由批次设计确定；发现冲突交负责人修订设计，不按文件名或目录放行。
- “固定版本”须包含卡中列出的每个被审交付目标的快照路径；复跑与证据须是本次运行内生成、退出码为 0 的 record。确实无法复跑时写“未复跑原因：…”，此时只要求引用有效 record。
- 非阻断建议写在“非阻断建议：”下逐行“- ”，由脚本并入批次分诊。
