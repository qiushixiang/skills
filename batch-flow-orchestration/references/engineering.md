# 工程与验证规范

执行者、审阅者（含第三方）和技术负责人共用本规范。它规定判断标准，不增加流程节点。

**第一证据是实际实现的代码，以及针对验收目标、可以重复运行、并且本次实际通过的构建和测试。**

## 复杂度与最小改动

- 先弄清目标、非目标、已有契约和验收边界，再动手。
- 优先复用已有能力；不为未来的扩展预先搭框架、平台或抽象。
- 抽取帮助函数要有实际价值：被复用、是独立概念、或能隐藏复杂的边界情况。简单的一次性逻辑不要拆散。复杂流程要让主路径清晰，细节就近命名。
- 未知输入只在负责它的边界验证一次；契约或类型已经保证的值，不要层层重复防御。
- 异常处理只针对实际可恢复的情形，不吞掉错误来制造“成功”。
- 假想的极端并发、安全或资源问题，不能自动扩大范围。要增加复杂度，先说明具体可达的失败、发生条件和代价；超出授权就上升，交负责人或用户决定。已有的明确安全契约仍必须满足。
- 遵循目标仓库现有的语言和工程规范，不把别的项目的风格当成通用标准。
- 只改本单范围内的东西。范围外发现的问题写进“候选新项”，不顺手修。受保护路径（计划中的 `protected`）不得改动，需要改就上升。

## 必要验证

- 复用已有的验证，只为三类内容补测试：验收项、原缺陷的反例、改动的直接影响。不凑测试类别、数量或覆盖率，不在测试里镜像实现逻辑，不新造通用测试平台。
- 优先用真实实现验证。确实需要隔离外部依赖时，只用最小的替身。模拟环境下的 PASS 不能代替目标行为的证据。
- 必须确认目标真的运行了：空输入、零个测试目标、只做静态扫描、只看到退出码 0，都不能单独证明验收。
- 必需的验证没有运行，就不能算通过：在“未运行/失败”行写明哪一项、原因和最小缺项。外围项允许跳过时，写 SKIP 和原因。
- 纯设计类的交付不要虚构实现验证；不为材料格式重复运行；已经有充分的原始结果时直接引用，不重跑。
- 需要宿主权限的验证，只能直接调用计划里的受控入口，不组合命令，也不另套 shell。

## 证据标准

- **只有两种文件算证据**：`bf/cli.py --base <任务>/.batch-flow record [--cwd D] -- <命令>` 和 `… snapshot --repo R --paths …` 生成的记录。手写的文件、自述、手抄或摘录的输出都不算；交付里引用它们会被退回。
- **通过要有本次运行的证据**：实施或返修交付 VERIFIED、审阅交付 RELEASE，都必须至少引用一份**本次运行开始之后生成、退出码为 0** 的 record。旧记录可以作为背景引用，但不能单独支撑“通过”。
- 失败的命令同样会留下记录。不能只看文件存在就判断通过，要看退出码和输出内容。
- 日志和报错由工具原样保存，不改写、不重排。交付里只写“验收项 → 证据路径”的对应关系，以及哪些已证明、哪些未运行或受阻、哪些待决定。
- 证据文件生成后不再修改。证据的哈希一旦不符，依赖它的工作就会被挡住。
- 记录数量、日志字数、测试数量、文档篇幅都不是进展指标。同一内容只维护一处，不建日报、风险报告、手工索引或进度表。

## 固定版本

- 计划列出 `repos` 时，驱动器在每次运行结束后自动为本次改动的文件做快照，这份快照就是本次交付的版本。“改动与版本”行写这份快照或提交哈希，不用另外手工 snapshot。
- 只算本次运行的改动；基线里已有的修改和其他批次的改动，都不算本批产出。
- 审阅结论只对被审的版本有效。“固定版本”行必须包含审阅卡列出的那些快照路径。代码之后再变，就会重新审阅，旧结论不能沿用。
- 源码不在 Git 里时，用 record 运行一条导出差异的命令来留下版本依据，不强迫建仓或提交。

## 审阅边界与问题处置

**检查观点**：按本审阅组的目标、验收和契约确定看什么，不机械地套用全部风险类别。集成批次只按约定的集成目标放行，其他功能的成熟度列为后续事项；但明确的安全、性能、资源契约仍可以阻断。

**阻断与非阻断**：

- 阻断必须同时满足三点：对应本组的目标、契约或验收；有实际可达的失败；能说清影响。
- 证明不了的事项写成“非阻断建议”，会进入本批分诊。
- 不要求作者反证所有假想的极端情况，不以代码风格阻断。
- 没有阻断就给 RELEASE，不因为还有建议而扣留。
- 缺少必需的证据，判 FIX_REQUIRED，关闭条件写“补齐某验收项的 record”。

**关闭条件的写法**：

- 每个阻断项一行，指定返修目标，返修目标必须是本组的交付目标。
- 写一句可核验的关闭条件：用什么命令或观察、看到什么结果，就算关闭。例如“`<测试>` 在 <场景> 下退出码 0 且输出含 <关键行>”。不要写“改好”“完善”。
- 要改方案、契约或受保护资产才能关闭的，标“方案级：是”，交负责人处理。

**复审范围**：

- 逐项核对列出的阻断项是否关闭，以及修复的直接回归，不凭旧结论。
- 复审中发现本组目标内的新阻断，照常列出；不借复审全量扩大范围。

**独立复跑**：

- 至少亲自复跑一项关键验收，并引用本次生成的 record。
- 代价过高（如整机全量构建）或环境禁止时，写“未复跑原因：<原因>；已核对：<原始记录与产物>”。
- 审阅只写 `records/`，不改被审对象。改了其他文件，交付会被判为不合法。
